Try it in a real development session.

Content Shelf keeps approved storyboard text and asset references beside your authoring tool. This pilot checks whether it reduces searching, switching windows, and copying the wrong content.

Your test answers are saved in this browser only. They are not sent automatically. At the end, download your results and send the file to your UAT coordinator.

A focused first pilot

Suggested group: 2 course developers and 1 instructional designer. Allow 45–60 minutes per tester, plus a short real development task. Use Windows 11 with Chrome first; run a separate pass in Edge if your team uses it.

  1. Use Project settings → Load sample lesson if needed. Choose Build in Rise to test the original developer checklist, or Prepare content (ID) to review imported Word content. Keep a blank Rise lesson or another text destination beside it.
  2. Complete the checks below. Use a small, approved storyboard extract for your own content.
  3. Build 3–5 blocks using the shelf. Compare this experience with your usual Word-to-authoring workflow.
  4. Download the results report and your sample project JSON. Share only approved content and redact screenshots if needed.

Ready for a wider pilot when: no unresolved blocker or major issue affects copying, saving, importing, image handling, or progress; the full checklist is complete; and testers confirm the workflow helps during actual development. Automated insertion into Rise is outside this MVP.

What this version includes

Import Word storyboards with a review preview; use Prepare content (ID) and Build in Rise modes; paste and split text into labeled pieces; edit notes; attach images; copy text and filenames; reorder, duplicate and delete blocks; undo the last project change; track insertion; import/export one active project; use a synchronized companion window.

  • Copying uses plain text. Bold, tables, and Word formatting are not retained.
  • Use Export handoff (ID) or Save project backup (developer) for backup. Clearing browser data removes local content. Browsers and computers do not sync automatically.
  • One project is active per browser and site. Opening a handoff replaces it; Word import offers replace or append. Export first when you need a separate copy. Undo covers the last change in the current window and is cleared by reload or an update from another window.
  • If a saved project cannot be read, recovery mode preserves the original data and offers a recovery download before you start again.
  • Images: PNG, JPEG, WebP or GIF, up to 2 MB each. Projects: up to 500 blocks and 100 content pieces per block; Word and JSON import limit 15 MB. Word imports attach up to 6 MB of supported image data in total; additional images are flagged for manual attachment. Available browser storage may be lower.
  • The companion is a normal browser window. Pop-ups may need to be enabled. It does not stay above other applications automatically.
  • Word import supports the supplied Rise storyboard format: S01-B01-style block headings and Field / Approved content tables. Other layouts need conversion first. No automatic Rise insertion, cloud project storage, shared editing, or central feedback collection.
